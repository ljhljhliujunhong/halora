# Halora

自己的 [Grok Build](https://x.ai) 桌面界面。打开它，选一个项目，就能直接跟 Grok 说话，不用盯着命令行。

中文名：星环。

## 需要什么

电脑里已经装好并登录过 Grok Build。Halora 调用的就是这份 Grok，能力没有另外阉过。

## 怎么跑

```bash
npm install
npm start
```

打包成 Windows 应用：

```bash
npm run pack
```

完成后，项目目录里的 `星环.exe` 就是最新版。双击它，或运行 `打开星环.bat`。

构建唯一来源由 `package.json` 的 `build.directories.output` 指定，目前为 `E:/VsCodeProject/Agent缓存文件/halora-release`。安装时校验包版本、源码/界面内容以及全部文件的 SHA-256。根目录启动器固定启动 `runtime/app/Halora.exe`。

应用运行时，新包会暂存在 `E:/VsCodeProject/Agent缓存文件/halora-updates`；Halora 收到更新事务后保存恢复状态并正常退出，后台安装器原地替换 `runtime/app`，复核全部文件后自动重启。更新时会短暂创建 `runtime/.rollback-*`，成功后立即删除；替换失败则恢复原程序。重启电脑中断安装后，再运行根目录启动器会继续待完成的更新；恢复安装需要本机 Node.js 仍在原位置。

## 目录说明

```text
GrokBuild/
  src/                React 界面、消息渲染与交互
  electron/           桌面主进程、Grok 接入及本地服务
  scripts/            图标、安装、更新与旧产物清理脚本
  tests/              回归测试
  public/             原始静态资源
  build/              打包图标（自动生成）
  dist/               前端构建结果（自动生成）
  node_modules/       本项目开发依赖
  runtime/            安装后的程序（不进入版本控制）
    app/              唯一一份当前程序
  星环.exe            日常使用的固定启动入口
  打开星环.bat        同一入口的批处理快捷方式
```

安装器只保留 `runtime/app/`。新程序在缓存目录完成构建和哈希校验，应用退出后才进入安装目录；原程序只作为本次更新的临时回滚副本，安装校验成功后立即删除。开发服务器不会监听这些安装产物。

升级后可运行 `npm run tidy` 删除历史遗留的根目录 `halora-app*`、`release` 和 `pack-out`。脚本先校验当前版本，并拒绝删除含有 Git 跟踪文件或无法确认内容的目录。

用户设置、草稿与检查点仍位于系统的 Halora 用户数据目录，Grok 登录与会话仍使用本机 Grok 数据目录，不随安装目录迁移。`src/App.jsx` 与 `electron/main.cjs` 仍较大，后续可按会话、侧栏和 IPC 服务逐步拆分；目录整理不混入业务逻辑重构。

## 0.2.2 可靠性改进

- 重复消息按来源边界处理，不再按文字前缀全局删除；历史工具输出和导出保留完整内容。
- 发消息/压缩在五分钟无任何会话更新后超时断开；等待权限时延长为三十分钟。取消立即结束本地等待，最多等待五秒确认；未确认会重连共享 Grok 进程，其它运行会话会标记为中断。
- 新检查点采用压缩内容寻址存储，未变化的文件复用数据；每项目保留最近三十个自动检查点，手动检查点保留，空间上限 256 MB。旧版检查点仍可恢复。快照、备份和定期会话索引在后台线程处理。
- Git 同步先展示操作和远程分支，确认后重新核对状态；只允许快进拉取，拒绝脏工作区和分叉，不自动创建合并提交。
- 权限请求改为可收起的独立面板；自动允许优先使用本次授权。
- 外观设置不依赖 Grok 配置可写；修改压缩阈值时单独同步配置，失败会显示具体原因。
- 设置页可查看存储、清理七天以上未被草稿或历史引用的附件，以及三十天以上的安全备份（最近三份保留），并导出轮转诊断日志。删除对话后草稿同步清除，原始会话进入本机 `trash` 待清理。
- 备份支持可选密码加密（AES-256-GCM）；旧的未加密备份仍可使用。恢复加密备份时，恢复前的安全备份使用相同密码。密码不写入设置；遗失密码无法恢复。
- 消息中的远程图片默认显示为链接，点击后在浏览器查看。界面错误提供日志出口；连续进程崩溃两次后停止自动重载。

## 怎么用

1. 选一个项目文件夹。
2. 在下面的输入框里打字，回车发送。
3. 它要改文件或跑命令时，会先问你。
4. 左边按项目看对话，也可以同时开着几个窗口跑。

## 0.2 工作区功能

- 并行会话的权限请求分别排队，可以选择会话处理；停止任务会清理对应请求。
- 草稿、图片附件和待发队列会保存到本地。退出时提示正在运行的任务；重启后可查看中断任务并准备继续，待发队列需主动恢复发送。
- 额度查询失败时显示上次结果、更新时间和缓存标记；没有历史结果时显示暂不可用，并在后台重试。
- 侧栏新增改动审查、检查点、导出备份和设置。
- 改动审查支持文件差异、暂存、取消暂存以及提交已暂存文件。需要 Git 仓库根目录。
- 设置包含默认模型、权限模式、压缩阈值、发送快捷键、默认项目、主题、字号和恢复选项。
- 文件检查点支持自动或手动建立、恢复预览，以及恢复前自动备份。包含 Git 跟踪的文件和未忽略的新文件，上限 10,000 个文件、64 MB；忽略文件和嵌套仓库不在范围内。恢复不会改变暂存区。
- 对话回退使用 Grok 提供的回退点，执行前保存原始会话副本，并明确使用仅回退对话模式。旧版 Grok 不支持接口时会显示错误。
- 当前对话可导出 Markdown、JSON、HTML。附件记录保留路径，导出文件不内嵌附件。
- `.halora` 备份包含本机 Grok 会话、用户技能、Halora 设置、草稿、附件和文件检查点，不包含登录凭据。上限 256 MB、30,000 个文件。恢复前会备份现有数据，同路径覆盖、其它数据保留，随后重启应用。跨机器使用时需重新选择本地项目路径。

运行 `npm test` 验证恢复、权限队列、额度降级、文件审查和备份流程；运行 `npm run build:ui` 构建界面。
